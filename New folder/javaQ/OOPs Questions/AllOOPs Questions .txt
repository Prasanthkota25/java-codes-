6:When should you use an Abstract Class versus an Interface? Can an interface have a constructor?


// abstract  class 


Abstract class used when the class shares  common behavior  and state 

features : 
>> can  have abstract methods 
>> can have normal methods
>> can have constructors 
>> can have  instance variables 


Ex................

 abstract class Animal {
		abstract void sound();

		void eat() {
			System.out.println("Eating .....");
		}

		static class myDog extends Animal {
			@Override
			void sound() {
				System.out.println("my dog is barking ");
			}
		}

		public static void main(String[] args) {

			Animal mydog = new myDog();
			mydog.eat();
			mydog.sound();
		}
	}
	
	
// interface 

used to define  a contract (what a class  must do)

features : 
>> methods are abstract  by defualt 
>> variables  are public state files 
>>  supports multiple inheritance 



Ex ..........

	interface flyable {
		void fly();
	}

	static class birds implements flyable {
		public void fly() {
			System.out.println("All birds are flying in the sky ....");
		}
	}

public static void main(String[] args) {
	flyable mybird = new birds();
	mybird.fly();

}



When to use?
Use Abstract Class when:
Classes share code
Need constructors or fields



Use Interface when:
Only behavior is required
Multiple inheritance needed


Can an interface have a constructor?
No.
Interfaces cannot have constructors because they cannot be instantiated.

7: What is it, and how does your specific language (Java) solve the issue of multiple inheritance?

Multiple inheritance means:
A class inherits from more than one parent class.
Example problem:
class A
class B
class C extends A, B



This can cause the Diamond Problem:
If both A and B define the same method, C doesn't know which one to use.
Java Solution
Java does not allow multiple inheritance with classes.



Instead, Java allows multiple inheritance using interfaces.


Example:
interface A {
    void methodA();
}
interface B {
    void methodB();
}
class C implements A, B {
    public void methodA() {}
    public void methodB() {}
}

8: What happens when you apply the final (or const) keyword to a class? To a method? To a variable?

 
 
 in java The Final Keyword is used 
 
 >>> Final class 
 >>> Final Method 
 >>> Final variable 
 

 
 Final class :

> the class  cannot be  subclassed  (no other  class  can  extend  it ).
> prevent  inheritance  to keep  the  class behavior  fixed  and secure 

Ex >..

final class Vehicle {
    // class implementation
}

// This is NOT allowed:
class Car extends Vehicle {} //  Compile-time error
 
 
 
 Final Method : 
 
> the method cannot be overridden is any subclass. 
> ensure that the behavior of the method remains  unchanged  in subclass

Ex ...

class Vehicle {
    final void startEngine() {
        System.out.println("Engine started");
    }
}

class Car extends Vehicle {
    // Cannot override startEngine():
    // void startEngine() { ... }  Compile-time error
}


Final variable : 

> the variable values  cannot be changed after the initialization 
> For primitive types, the value is constant.
> For objects, the reference is constant, but the object’s contents can still be modified.
 
 
 Ex with  the primitive .....
 
 
 final int MAX_SPEED = 120;
MAX_SPEED = 150; //  Compile-time error



Ex with the object ...

final List<String> names = new ArrayList<>();
names.add("Alice");       //  Allowed
names = new ArrayList<>(); //  Not allowed (cannot change reference)



 
final on class → no inheritance

final on method → no overriding

final on variable → constant value/reference
 
 
 Java designers wanted to simplify the language.

Instead of having two keywords (const and final) for constants, they chose only final.

final can make variables constant, but for classes and methods, it also controls inheritance and overriding.

const is reserved but not used, so writing const in Java will cause a compile-time error.
